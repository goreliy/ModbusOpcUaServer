# Встроенный MCP: Codex / Claude → OPC Modbus Server

MCP входит в `opc-modbus-server.exe` и в сервер, запускаемый из GUI. Отдельный
пакет или Python для работы MCP не нужен. Полная сборка не имеет trial-таймера.

## Подключение

Сначала сохраните рабочий JSON-конфиг. Для каждого экземпляра используйте
свой файл, каталог данных и свободные порты. MCP по умолчанию слушает
`http://127.0.0.1:14840/mcp`; в конфигурации можно указать:

```json
"mcp": { "enabled": true, "host": "127.0.0.1", "port": 14840 }
```

`port: 0` выбирает свободный порт. `host` допускает только loopback IP.
`enabled: false` отключает управление MCP. Для общего сервера через STDIO/GUI
оставьте HTTP включённым: STDIO автоматически подключается к локальному endpoint.
Адрес, порт и enabled применяются после закрытия и повторного запуска
контроллера. Настройки есть в GUI в разделе «Общие и логи».

Для **Codex** добавьте в его `config.toml` (замените оба пути своими):

```toml
[mcp_servers.opc_modbus]
command = 'D:\123321\rust opc_ua 20 test\dist\windows\opc-modbus-server.exe'
args = ['mcp', '--config', 'C:\ProgramData\OPC Modbus Server\config.json']
```

В UI настройки MCP: имя `opc_modbus`, тип STDIO, command — полный путь к EXE,
три отдельные строки arguments: `mcp`, `--config`, полный путь к JSON.
После подключения проверьте `server_status` и `get_config`.

Для **Claude Code** аналогичный проектный `.mcp.json`:

```json
{
  "mcpServers": {
    "opc_modbus": {
      "type": "stdio",
      "command": "D:\\123321\\rust opc_ua 20 test\\dist\\windows\\opc-modbus-server.exe",
      "args": ["mcp", "--config", "C:\\ProgramData\\OPC Modbus Server\\config.json"]
    }
  }
}
```

Такие же `command` и `args` подходят для `claude_desktop_config.json`;
для Claude Desktop поле `type` можно опустить.

Команда вручную: `opc-modbus-server.exe mcp --config config.json`.
Она предназначена для клиента JSON-RPC: stdout содержит только сообщения MCP.

## Привязка к экземпляру и порядок запуска

MCP-процесс `opc-modbus-server.exe mcp --config <полный путь>` запускается
самим Codex/Claude и подключается только к контроллеру выбранного JSON.
Если конфигуратор или сервер ещё не открыт, MCP сразу проходит инициализацию,
показывает инструменты и возвращает `server_status.attached: false`.
При появлении выбранного экземпляра мост подключается автоматически.
Другой сервер или скрытый `mcp-host` мост не запускает.

Конфигуратор сам открывает контроллер выбранного файла. Если этот файл уже
обслуживает консольный сервер или служба Windows, он подключается к ним.
Опрос, OPC UA и конфигурация остаются общими. `run`/служба, запущенные после
конфигуратора, используют его контроллер и запускают опрос в нём.
Закрытие GUI, владеющего контроллером, завершает его; MCP-клиент остаётся
в Codex/Claude и ждёт повторного открытия. Закрытие GUI, подключённого
к отдельной службе или серверу, их не останавливает.

В разделе «Сервер» показаны имя экземпляра, идентификатор выбранного файла
и полный путь. Кнопки копирования создают уникальное имя подключения
`opc_modbus_<имя>_<идентификатор>` и аргументы с точным путём к этому файлу.
Для другого экземпляра скопируйте настройки из его окна конфигуратора.
Два окна с одним файлом относятся к одному экземпляру; разные файлы — к разным.
Если предпочитаемый MCP-порт занят другим экземпляром, выбирается свободный;
актуальный адрес отображается в GUI и находится через файл подключения.

`server_stop` останавливает опрос и OPC UA, сохраняя управление и настройки.
`shutdown_controller` закрывает текущий контроллер. Мосты ждут следующего запуска.
Неопределённо завершённые изменяющие запросы автоматически не повторяются.

## Инструменты

| Задача | Инструменты |
|---|---|
| Статус, метрики, OPC UA сессии | `server_status`, `server_start`, `server_stop`, `server_restart`, `shutdown_controller` |
| Конфигурация | `get_config`, `validate_config`, `set_config`, `patch_config`, `apply_config` |
| Каналы, приборы, группы опроса | `list_devices`, `upsert_channel`, `delete_channel`, `upsert_device`, `delete_device`, `upsert_poll_group` |
| Теги и формулы | `upsert_tag`, `delete_tag`, `get_tag`, `set_formula`, `test_formula`, `read_tags`, `write_tag` |
| Поиск и Modbus | `list_serial_ports`, `start_scan`, `scan_status`, `cancel_scan`, `read_modbus`, `write_modbus` |
| История и диагностика | `get_history`, `get_logs`, `get_audit` |
| Проверка файловых прав и хранилища без опроса | `check_access` |
| Готовые строки подключения и абсолютные пути | `connection_info` |

## Откуда загружается конфигурация

GUI поддерживает `opc-modbus-config.exe --config полный-путь-к-config.json`.
Без аргумента он сначала ищет `config.json` рядом с EXE, затем установленный
`C:\ProgramData\OPC Modbus Server\config.json`; для новой пользовательской
установки создаёт рабочий файл в LocalAppData. Относительные пути данных,
логов и PKI разрешаются от каталога выбранного конфига.
Раздел «Сервер» показывает абсолютные пути и ревизии сохранённого/применённого
конфига. Кнопки «Копировать настройки Codex», «Копировать настройки Claude» и
«Копировать команду MCP» формируют настройки из действительных путей EXE и
конфига. Те же строки выдаёт `connection_info` через MCP и CLI-команда
`opc-modbus-server.exe mcp-info --config config.json`.

Ресурсы `opcmodbus://config`, `opcmodbus://status`, `opcmodbus://examples`
дают конфигурацию, состояние и готовые примеры объектов. Каждый инструмент
публикует схему аргументов; результат содержит текст и `structuredContent`.

## Изменения на ходу

1. Получите `get_config`. `revision` — SHA256 сохранённого файла;
   `active_config` и `applied_revision` показывают работающую конфигурацию.
2. Передайте `expected_revision` в инструмент изменения. Устаревшая ревизия
   отклоняется. Можно сначала использовать `dry_run: true`.
3. По умолчанию файл атомарно сохраняется с одной резервной копией `.bak`,
   затем применяется без перезапуска процесса. `apply: false` только сохраняет
   кандидат; применить его можно через `apply_config` с новой ревизией.
4. Каналы, приборы, теги, группы и формулы меняются на ходу. Циклы и неизвестные
   зависимости отклоняются до сохранения. `patch_config` использует JSON Merge
   Patch: объекты объединяются, массивы заменяются целиком, null удаляет поле.

Пример установки формулы:

```json
{
  "tag": "meter.temperature",
  "formula": "raw * 0.1 + tag(\"temperature.offset\")",
  "expected_revision": "SHA256 из get_config"
}
```

Обратная формула задаётся `write_formula`, например `value * 10`; null
снимает формулу. Каскадный пересчёт использует значения до deadband публикации.
`read_tags` и `get_tag` возвращают отдельно `published` и `calculated`.
`test_formula` проверяет выражение без доступа к приборам:

```json
{ "formula": "raw * 0.1", "input": 123 }
```

Endpoint/безопасность OPC UA, логирование и каталог данных требуют остановки
backend: `server_stop`, изменение конфигурации, `server_start`. Изменение
настроек самого MCP требует повторного запуска его владельца.
Пароли и хэши скрыты в ответах: для сохранения существующих секретов меняйте
только нужные поля через `patch_config`; полный `set_config` с `<redacted>`
отклоняется. Хэш нового пароля можно создать CLI-командой `hash-password`.

## Поиск приборов

На работающем канале:

```json
{
  "channel_id": "rs485", "unit_start": 1, "unit_end": 247,
  "function": 3, "address": 0, "quantity": 1,
  "timeout_ms": 200, "delay_ms": 20
}
```

Для новых адресов передайте `transports` вместо `channel_id`:

```json
{
  "transports": [
    { "type": "tcp", "host": "192.168.1.10", "port": 502 },
    { "type": "rtu", "path": "COM3", "baud": 9600, "parity": "even", "data_bits": 8, "stop_bits": 1 }
  ],
  "unit_start": 1, "unit_end": 16
}
```

Указывайте согласованные параметры COM и известный диапазон сетевых адресов.
Несколько кандидатов TCP/RTU можно передать списком; автоматического поиска
всей сети и угадывания модели прибора нет. Найденный прибор — подтверждённый
стандартный ответ или exception от адресата; gateway errors не считаются прибором.
Регистровая карта и идентификация модели требуют документации производителя.
Поиск ничего не добавляет в конфиг автоматически.

`start_scan` сразу возвращает `job_id`. `scan_status` даёт прогресс и результаты
с пагинацией, `cancel_scan` отменяет между завершёнными запросами. Пока идёт
автономный поиск, запуск основного опроса запрещён до освобождения соединения.
На работающей шине чтение проходит через её очередь, не прерывая обычный опрос.
Для активного RTU-over-TCP используйте `channel_id`, чтобы не открыть второй
путь к той же физической шине. Запросы ограничены таймаутом; четыре активных
задачи и предел результатов защищают память, это не trial-ограничение продукта.

## Запись и локальный доступ

`write_tag` использует инженерные единицы и активную обратную формулу;
`write_modbus` поддерживает FC05/06/15/16 для настроенного устройства.
Обе требуют `confirm: true` после подтверждения человеком конкретного
тега/адреса/значения и `expected_revision` из `applied_revision`.
При остановленном сервере raw-запись требует ревизию сохранённого файла.
Успех означает полученное подтверждение Modbus, broadcast запрещён.
Останов, перезапуск и закрытие контроллера тоже требуют `confirm: true`.

HTTP защищён Bearer-токеном и проверками Host/Origin. Токен создаётся в
`<config.json>.mcp-endpoint.json`, stdio читает его автоматически. Файл
предоставляет доступ писателям выбранной конфигурации Windows (Unix: 0600), поэтому явно
разрешённый оператор подключается к службе SYSTEM без запуска Codex/Claude
от администратора. Не публикуйте токен или этот файл.
Прямой HTTP-клиент берёт `url` и токен из этого файла;
POST `/mcp` — Streamable HTTP с JSON-ответом, GET даёт 405,
DELETE с `Mcp-Session-Id` удаляет регистрацию HTTP-клиента.
Журнал MCP содержит имена операций и итог, без аргументов и паролей.

Установщик предоставляет право Modify на каталог данных только выбранному
Windows-пользователю (`OperatorSid`); SID исходного пользователя сохраняется
при повышении прав через UAC. Для ранее установленного каталога запустите
`repair-data-permissions.ps1`: он запросит повышение прав и исправит права
только этого пользователя, без изменения конфигурации приборов.
Проверка без запуска опроса: `opc-modbus-server.exe check-access --config config.json`
или инструмент `check_access`. Проверка создаёт временные файлы и открывает
хранилище, но не обращается к COM/TCP-приборам. При занятой базе будет показан
конкретный путь и ошибка блокировки; хранилище нельзя открывать двум серверам.

## Проверка реализации

`cargo test -p svc-host --test mcp` проверяет настоящий HTTP и локальный Modbus
TCP-симулятор: CAS, атомарное сохранение, формулы, запись, поиск, отмену,
продолжение опроса и одно транспортное соединение. GUI-тест проверяет
удалённый запуск/останов и сохранение опроса после закрытия GUI.
`scripts/check-mcp.py --exe ...` проверяет stdio и HTTP официальным Python MCP
SDK, подключение нескольких клиентов к тому же экземпляру, продолжение
опроса после EOF и явное завершение через `shutdown_controller`.
Это проверки на симуляторах; приёмка на реальном RTU выполняется отдельно.

Протокол: [MCP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports),
совместимые версии 2024-11-05, 2025-03-26, 2025-06-18.
Подключение клиентов: [Codex MCP](https://developers.openai.com/codex/mcp),
[Claude Code MCP](https://code.claude.com/docs/en/mcp).

## Состояние клиентов и порядок запуска

В разделе «Сервер» конфигуратор показывает число MCP-клиентов, имя и версию
из `initialize.clientInfo`, тип подключения (stdio/HTTP) и короткий идентификатор.
Сам конфигуратор не учитывается как внешний MCP-клиент.
STDIO-мост проверяет связь каждую секунду, удаляет регистрацию при EOF и
переподключается после смены контроллера. При аварийном завершении клиента
регистрация истекает через 60 секунд без heartbeat. HTTP-сессия удаляется
через DELETE либо истекает через 60 секунд без запросов.

GUI, MCP-клиент и `run`/службу можно запускать в любом порядке с одним JSON.
GUI открывает контроллер, а STDIO ожидает выбранный GUI/сервер. `run`/служба
подключаются к уже существующему контроллеру и запускают опрос в нём.
Запросы, прерванные транспортной ошибкой, не повторяются автоматически:
изменение оборудования могло уже произойти. Восстановление подключения
повторяет только MCP-инициализацию.

Файл подключения Windows доступен только писателям выбранной конфигурации;
разрешения только на чтение не дают доступа к токену управления.
Поэтому служба LocalSystem и явно разрешённый оператор используют один endpoint,
а разрешения каталога не расширяют доступ к токену.
